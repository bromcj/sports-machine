# Review, 2026-09-24: can the owner rely on this?

The first outside review of the whole program: code, data and production,
tested rather than read. Ground truth written before any report was opened:
[review-independent.md](review-independent.md). Every claim in the cleanup's
handoff, marked true or false: [review-claims.md](review-claims.md). What the
second sweep deleted: [sweep-pass2.md](sweep-pass2.md).

## 1. Verdict

**Not yet safe to rely on — but it is now honest, it no longer loses data,
and it no longer switches itself off.**

The core holds up. The program **cannot bet real money**: every sport is
refused, nothing automated can switch it on, and the three gates behave
exactly as their rules say when fed test inputs. The headline result —
**the baseball model loses to the bookmakers' closing prices in all three
test seasons** — was re-derived from the raw data with independent code and
matches to six decimal places. The grading arithmetic matches a hand
calculation to the last digit.

What was not safe was everything around that core. At the start of this
review:

- **paper betting had silently stopped** — from today on, no game could be
  matched to its prices, so gate 2 could never have filled;
- **the scheduled job would have switched itself off tonight**, and stayed
  off, while the alerts file said "All clear";
- **live predictions used different numbers from the model that was tested**
  (the ballpark factor), so gate 2 was measuring a different model from gate 1;
- **the safety net was mostly decoration** — CI had been failing for 11
  pushes, the golden test checked zero feed matches, and five of six
  deliberate breakages went unnoticed by the tests CI runs.

All of that is fixed, tested, pushed and running in production. Two things
keep the verdict at "not yet": a measurement problem inside gate 2 that only
the owner can decide (section 3, item 1), and the fact that the fixes have not
yet been through a scheduled run — the first is **today at 11:30am**.

## 3. What was wrong and is not fixed

1. **Gate 2 mixes two ways of measuring the fair price** — *owner's decision*.
   When Pinnacle has no price at bet time, the "fair" price is an average of
   the other books; at the close it is usually Pinnacle. All four bets graded
   so far switched source, and the switch is 35–45% of each graded value.
   Pinnacle is missing for up to half the games in some pulls, so this keeps
   happening. It is gate logic, so it was left alone. *What it would take:*
   grade `info` only when both ends use the same source.
2. **Paper bets can use prices up to 14 hours old.** Any move in that gap is
   credited to the model. *What it would take:* a maximum price age in
   `place()` — the owner picks the limit.
3. **Training and live compute some inputs slightly differently** the day
   after an off day (11–16% of training rows). Not leakage; a model change.
   *What it would take:* one shared function, a retrain, a new gate-1 record.
4. **The closing-price table is not maintained**; it is rebuilt by hand, still
   holds the 46 doubleheader games and 18 closes taken over an hour early.
   *What it would take:* `python resolve_market_close.py --rebuild`, then
   `python run_daily.py refresh`. The verdict cannot flip.
5. **The cloud's credit use is invisible locally**; the monitor watches the
   props key only. *What it would take:* export the cloud's usage rows with
   the archive.
6. **82 MB of paid historical odds are in the public repo** (`archive/` is
   append-only by the owner's rule). *What it would take:* the owner's
   decision, and a history rewrite if they must go.
7. **Phase 3 never built what its brief asked**: flags logged as `mode='shop'`
   paper bets and graded. The code only prints them (the docs now say so).
8. **Gate 2 has checks that switch off when an input is missing** and is not
   tied to the model gate 1 tested. Not reachable through today's code; gate
   logic, reported only.
9. **The purchased props data (~16,600 credits) is in no backup** and lives
   only in the dev folder. *What it would take:* copy
   `sports-machine-dev/data/props/` somewhere safe.
10. **Two backups in the rotation are of a test copy** (`-0019`, `-0025`).
    Harmless; they will age out.

## 4. What was claimed and confirmed

- Real money is refused until all three gates pass; a placeholder never clears
  gate 1; gate 2 needs 50+ graded bets, 3 standard errors and 75% coverage; a
  passing placebo blocks it; `arm()` refuses without gates 1 and 2; nothing
  automated calls it.
- MLB gate 1 (−0.008158, t = −4.86, 6,533 games) and Part E's E5 (+2.73
  points, 536 games) reproduce from raw data.
- Hand-recomputed grading matches exactly; one real game traced from ingestion
  to grade is correct at every step; live features use only pre-game data.
- A restored backup reproduces the golden baseline exactly.
- The cleanup's one deletion was dead code, and its recovery command works.
- At the real betting cadence the 3-standard-error bar still holds a no-skill
  model to 1.2–1.8% (the docs had assumed a slower cadence).
