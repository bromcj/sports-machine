## What the numbers actually say

The tree is **15,223 lines, 22.8% prose**, 31 functions over 60 lines, 87 audit
checks, 111 tests, 44 files with `sys.path.insert`, 18 top-level modules and 9
top-level markdown files.

Two findings changed what the cleanup should do:

**Duplication is far smaller than it looked.** The first version of this tool
counted *call sites* and reported 61 duplicates of `fair_prob` â€” every one of
them a file correctly calling the single implementation. Counting usage as
duplication would have sent 1.3 after exactly the wrong thing. With call sites
excluded, the real total is **17 inline re-implementations across 5
calculations**, and only a handful matter:

- `status mapping` â€” `backfill.py:46` reads `abstractGameState` directly
  instead of going through `feeds.stats_api_status`. This is the one with
  teeth: that bypass is the shape of the postponed-game bug that cost 88 games.
- `UTC parsing` â€” 3 sites doing `.replace("Z", "+00:00")` by hand.
- `de-vig` â€” 2 sites in research/props code, each de-vigging inline.
- `fair probability` â€” 2 sites choosing sharp-else-consensus in their own way.
- `twin matching` â€” 4 hits, all of them prose mentioning `(date, away, home)`
  rather than code. No action.

**`finals` is undocumented in all three docs**, `predict` is missing from the
state doc, and `close`/`grade`/`morning`/`refresh` are missing from README.
`market` is documented, contrary to the brief's note.

## Order of work, and one scope decision recorded up front

1.2 golden test â†’ 1.3 prose and duplication â†’ **1.4 partial** â†’ 1.5
integration â†’ 1.6 dashboard.

**1.4 is deliberately not done in full, and this is the judgment call the
Autonomy section asks me to record.** The target layout moves everything into a
`sports_machine/` package, removes 44 `sys.path.insert` calls, and re-points
both workflows, both `.bat` files, the Task Scheduler entries and the prod
checkout at new entry points.

The golden test proves *behaviour* is unchanged. It cannot prove an *entry
point* still resolves â€” and the brief itself names the reason to be careful:
"a broken scheduled job is a silent outage". That risk lands on a machine that
has just started a time-sensitive collection run which cannot be re-bought at
this price.

So 1.4 does the parts that carry the value without that risk:

- move the one-off scripts (`props/b3_dryrun`, `check_thursday`, `preflight`)
  under `research/` next to the results they produced;
- move the stray root markdown (`docs-calibration.md`,
  `sports_machine_audit.md`, `CLAUDE_CODE_TASK.md`) into `docs/`;
- delete dead code: `features/registry.py`, the `bettime` snapshot type,
  the unused imports;
- split `audit.main` into one function per section behind the same runner;
- split the longest functions into named steps.

The package rename is left as the single largest remaining item, written up in
the handoff with what it would take. **Every import path, every entry point and
every scheduled job is untouched**, which is the conservative option.
